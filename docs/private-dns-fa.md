# Private DNS (اندروید) + لیست عمومی دامنه/آی‌پی/رنج

## ⚠️ یک محدودیت فنی مهم — قبل از هر چیز بخوانید

فیلد **Private DNS** اندروید (تنظیمات ← شبکه و اینترنت ← DNS خصوصی) فقط با
**DNS-over-TLS (DoT)** روی پورت 853 کار می‌کند. **Cloudflare Workers نمی‌تواند
چنین سروری میزبانی کند** — Worker فقط به رویدادهای `fetch` روی HTTP/HTTPS
جواب می‌دهد و نمی‌تواند یک TLS listener خام روی پورت 853 باز نگه دارد. این
یک محدودیت پلتفرم کلادفلر است، نه انتخاب طراحی این پروژه.

به همین دلیل این قابلیت از **دو بخش جدا** تشکیل شده:

1. **لیست عمومی دامنه/آی‌پی/رنج** — داخل همین Worker، در دیتابیس D1، قابل
   مدیریت از پنل ادمین (تب «🌐 Private DNS») و در دسترس عموم (بدون نیاز به
   ورود) از آدرس:
   ```
   GET https://<دامنه-ورکر-شما>/api/dns-rules
   ```
   که چیزی شبیه این برمی‌گرداند:
   ```json
   {
     "rules": [
       { "id": 1, "kind": "domain", "value": "*.example.com", "note": null, "created_at": 1730000000000 },
       { "id": 2, "kind": "cidr",   "value": "1.2.3.0/24",   "note": "رنج فیلترشده", "created_at": 1730000000000 }
     ],
     "cleanIp": "104.16.123.45"
   }
   ```
2. **سرور DoT مستقل** — کد کامل آن در پوشه‌ی [`dot-server/`](../dot-server) این
   مخزن است، ولی روی **یک VPS جدا** (نه روی Cloudflare) اجرا می‌شود. این سرور
   هر ۶۰ ثانیه یک‌بار لیست بالا را می‌گیرد و طبق آن تصمیم می‌گیرد.
3. **آدرس DoH داخل همین Worker** — روی مسیر `/dns-query` (کد در
   [`src/network/doh.ts`](../src/network/doh.ts)). چون DoH روی HTTPS معمولی
   (پورت ۴۴۳) کار می‌کند، برخلاف DoT نیازی به VPS جدا ندارد و مستقیماً روی
   همین Worker جواب می‌دهد — منطق تصمیم‌گیری‌اش دقیقاً همان منطق سرور DoT است
   (بالا)، فقط به‌جای گرفتن لیست از طریق شبکه، مستقیماً از دیتابیس D1 همین
   پروژه می‌خواند. **این جایگزینِ Private DNS سیستمیِ اندروید نیست** — آن
   فیلد فقط DoT را قبول می‌کند — ولی هر برنامه یا مرورگری که اجازه‌ی تنظیم
   یک آدرس DoH دلخواه را بدهد (فایرفاکس، اکثر برنامه‌های اندرویدی که از DoH
   سفارشی پشتیبانی می‌کنند، `curl --doh-url`، و…) می‌تواند مستقیماً به
   `https://<دامنه-ورکر-شما>/dns-query` وصل شود، بدون نیاز به هیچ زیرساخت
   اضافه‌ای. هم فرمت باینری استاندارد RFC 8484 (که تقریباً همه‌ی
   کلاینت‌های واقعی DoH از آن استفاده می‌کنند) و هم فرمت JSON گوگل/کلادفلر
   (`?name=&type=`، مناسب برای تست دستی سریع از مرورگر) پشتیبانی می‌شود.

## منطق تصمیم‌گیری سرور DoT

برای هر کوئری DNS که می‌رسد:

- اگر **دامنه‌ی درخواستی** با یکی از قوانین نوع «دامنه» تطبیق داشته باشد
  (تطبیق دقیق یا wildcard مثل `*.example.com`) → به‌جای resolve واقعی،
  مستقیماً بهترین **آی‌پی سالم کلادفلر** (همان که در تب «پنل‌ها / اکانت‌های
  کلادفلر» به‌صورت خودکار کشف و تست می‌شود) برگردانده می‌شود — یعنی ترافیک
  این دامنه از پروکسی کلادفلر همین پروژه رد می‌شود.
- در غیر این صورت، کوئری عیناً به یک resolver معمولی (پیش‌فرض:
  `https://1.1.1.1/dns-query`) فوروارد می‌شود و پاسخ واقعی گرفته می‌شود.
  - اگر آی‌پیِ برگشتی در پاسخِ واقعی داخل یکی از رنج‌های نوع «آی‌پی» یا
    «رنج (CIDR)» ثبت‌شده باشد (مثلاً رنج‌های شناخته‌شده به‌عنوان فیلتر/مسدود)
    → همان جایگزینی با آی‌پی سالم کلادفلر انجام می‌شود.
  - در غیر این صورت پاسخ واقعی دست‌نخورده برگردانده می‌شود (مستقیم).

**نکته مهم:** DNS فقط تعیین می‌کند «این دامنه به کدام آی‌پی resolve شود» —
نمی‌تواند مسیر بسته‌های شبکه‌ای که قبلاً یک آی‌پی مشخص دارند را عوض کند. پس
ورودی‌های «آی‌پی/رنج» فقط زمانی اثر دارند که آن آی‌پی **در پاسخ یک کوئری DNS**
ظاهر شود (یعنی کاربر دارد یک دامنه را resolve می‌کند که به آن آی‌پی خورده)،
نه برای اتصال مستقیمی که از اول با یک IP لیترال باز می‌شود.

## راه‌اندازی سرور DoT (روی یک VPS)

```bash
cd dot-server
npm install
cp .env.example .env
# .env را ویرایش کنید: DOT_HOSTNAME، مسیر گواهی TLS، و WORKER_BASE_URL
```

۱. یک ساب‌دامین (مثلاً `dns.yourdomain.com`) را به آی‌پی VPS اشاره بدهید.
۲. گواهی TLS بگیرید (مثلاً `certbot certonly --standalone -d dns.yourdomain.com`).
۳. بیلد و اجرا:
   ```bash
   npm run build
   sudo node dist/index.js   # یا از bndmax-dot.service.example برای systemd استفاده کنید
   ```
   برای اجرای دائم به‌عنوان سرویس، فایل نمونه‌ی
   [`bndmax-dot.service.example`](../dot-server/bndmax-dot.service.example) را
   به `/etc/systemd/system/bndmax-dot.service` کپی و مسیرها را اصلاح کنید، سپس:
   ```bash
   sudo systemctl enable --now bndmax-dot
   ```

## تنظیم روی اندروید

۱. تنظیمات ← شبکه و اینترنت (یا Connections) ← DNS خصوصی (Private DNS)
۲. گزینه‌ی «Private DNS provider hostname» را انتخاب کنید
۳. همان دامنه‌ای که در `DOT_HOSTNAME` گذاشتید را وارد کنید (مثلاً
   `dns.yourdomain.com`) — **بدون** `https://` یا پورت
۴. ذخیره کنید. اندروید خودش پورت 853 را با DoT امتحان می‌کند.

اگر گواهی TLS معتبر نباشد یا سرور در دسترس نباشد، اندروید به‌صورت خودکار به
DNS معمولی برمی‌گردد — یعنی این تنظیم هیچ‌وقت کاربر را کامل قطع نمی‌کند.

## مدیریت لیست

از پنل ادمین (`/admin`) ← تب «🌐 Private DNS» می‌توانید دامنه/آی‌پی/رنج
اضافه یا حذف کنید؛ سرور DoT حداکثر تا ۶۰ ثانیه بعد (یا مقدار
`RULES_REFRESH_SECONDS`) آن را می‌بیند، بدون نیاز به ری‌استارت.
