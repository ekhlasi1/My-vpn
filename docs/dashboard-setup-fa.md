# راهنمای راه‌اندازی پنل مدیریت، ربات تلگرام و دیتابیس

این پروژه حالا علاوه بر پروکسی VLESS، یک **پنل مدیریت کامل** (`/admin`) و یک **ربات تلگرام** برای صدور اشتراک تست/VIP دارد. داده‌ها (کاربران، تنظیمات، نشست‌های ادمین) در **Cloudflare D1** (دیتابیس SQL رایگان کلادفلر) ذخیره می‌شوند — چیزی که کلادفلر آن را بن نمی‌کند و بخشی رسمی از Workers است.

## ۱. ساخت دیتابیس D1

```bash
npx wrangler d1 create bndmax-vpn-db
```

خروجی این دستور یک `database_id` می‌دهد. آن را در `wrangler.toml` جای‌گزین `REPLACE_WITH_YOUR_D1_DATABASE_ID` کنید (این بخش از قبل به فایل اضافه شده):

```toml
[[d1_databases]]
binding = "DB"
database_name = "bndmax-vpn-db"
database_id = "همینجا آیدی واقعی را جایگزین کنید"
```

سپس جدول‌ها را بسازید:

```bash
# برای تست محلی
npx wrangler d1 execute bndmax-vpn-db --local --file=./src/db/schema.sql

# برای دیتابیس واقعی روی کلادفلر
npx wrangler d1 execute bndmax-vpn-db --remote --file=./src/db/schema.sql
```

## ۲. دیپلوی

```bash
npm run build
npx wrangler deploy
```

اگر از GitHub Actions برای دیپلوی استفاده می‌کنید، مطمئن شوید که `wrangler.toml` (با `database_id` واقعی) در ریپو کامیت شده باشد.

## ۳. اولین ورود به داشبورد

آدرس `https://<دامنه-شما>/admin` را باز کنید. چون هنوز رمزی تنظیم نشده، صفحه‌ی «راه‌اندازی داشبورد» باز می‌شود و از شما یک رمز عبور می‌خواهد. این رمز را در بخش «🔒 امنیت» داخل داشبورد هر وقت خواستید می‌توانید عوض کنید.

## ۴. اتصال ربات تلگرام

1. با @BotFather در تلگرام یک ربات بسازید و توکن آن را کپی کنید.
2. آیدی عددی خودتان (ادمین) را با پیام دادن به `@userinfobot` پیدا کنید.
3. داخل داشبورد به تب «🤖 ربات تلگرام» بروید، توکن و آیدی عددی ادمین (و یوزرنیم بدون @، مثلاً `vahidekhlasi`) را وارد و ذخیره کنید.
4. روی دکمه‌ی «🔗 فعال‌سازی Webhook» بزنید. از این لحظه ربات به‌صورت خودکار به آدرس `https://<دامنه-شما>/api/tg/webhook` وصل می‌شود.

### دستورات کاربر در ربات
- `/start` یا `/trial` — دریافت اشتراک تست جدید
- `/usage` — مشاهده میزان مصرف و زمان باقیمانده
- `/pro` — درخواست اشتراک VIP (به ادمین اطلاع داده می‌شود و به کاربر گفته می‌شود به @vahidekhlasi پیام دهد)

### دستورات ادمین در ربات (فقط برای آیدی تلگرام ادمین)
- `/addpro <آیدی_تلگرام> <روز> <حجم_گیگابایت>` — ساخت سریع اشتراک VIP
- `/deluser <uuid>` — حذف کاربر
- `/stats` — آمار سریع

## ۵. تنظیمات اشتراک تست

در تب «🎁 تنظیمات تست» می‌توانید مشخص کنید:
- مدت اعتبار تست (ساعت)
- حجم مجاز تست (مگابایت)
- فاصله‌ی زمانی لازم بین دو درخواست تست (کول‌داون، ساعت)

## ۶. مدیریت کاربران و اشتراک پرو

در تب «👥 کاربران»:
- فرم «افزودن اشتراک پرو»: با وارد کردن آیدی تلگرام، تعداد روز و حجم (گیگابایت)، یک اشتراک VIP ساخته و در صورت اتصال ربات، لینک به‌صورت خودکار برای کاربر پیامک می‌شود.
- جدول کاربران: مشاهده‌ی مصرف، وضعیت، غیرفعال/فعال‌سازی، تمدید ۳۰ روزه و حذف هر کاربر.

## ۷. شمارش حجم مصرفی و اعمال محدودیت‌ها

هر بار که یک کاربر (تست یا پرو) از طریق پروکسی وصل می‌شود، حجم رد و بدل شده اندازه‌گیری و در دیتابیس ذخیره می‌شود. یک Cron هر ساعت اجرا می‌شود (`[triggers] crons` در `wrangler.toml`) و:
- کاربرانی که زمان‌شان تمام شده را غیرفعال می‌کند.
- کاربرانی که حجم‌شان تمام شده را غیرفعال می‌کند.
- به کاربرانی که ۸۰٪ حجم خود را مصرف کرده‌اند هشدار می‌دهد (فقط یک بار).

> نکته: UUIDهای داخل متغیر `UUID` در `wrangler.toml` (تنظیمات فعلی شما) همیشه بدون محدودیت و به‌صورت دائمی معتبر باقی می‌مانند — این‌ها را می‌توانید برای کانفیگ شخصی خودتان نگه دارید، جدا از کاربران تست/پرو که از داشبورد یا ربات مدیریت می‌شوند.

## ۸. نکات امنیتی

- کوکی نشست ادمین `HttpOnly` و `Secure` است، پس داشبورد باید حتماً روی HTTPS (پیش‌فرض Workers) استفاده شود.
- رمز عبور با PBKDF2-SHA256 هش می‌شود؛ متن ساده در هیچ‌جا ذخیره نمی‌شود.
- توکن ربات تلگرام در دیتابیس D1 ذخیره می‌شود، نه در کد یا مخزن گیت — پس هنگام Push کردن پروژه در گیت‌هاب لو نمی‌رود.

## ۹. مدیریت چند اکانت کلادفلر (پنل‌ها / اکانت‌های اضافه)

از تب «🖧 پنل‌ها / اکانت‌های کلادفلر» می‌توانید هر تعداد ورکر اضافه (روی همین اکانت یا روی یک **اکانت کاملاً جدای کلادفلر**) اضافه کنید — بدون محدودیت تعداد.

**حالت ساده (فقط چرخاندن کانفیگ):** فقط «آدرس ورکر» را وارد کنید. کانفیگ‌های ۵گانه کاربران VIP بین ورکرهای فعال در گروه‌های چرخشی (batch) پخش می‌شوند، دقیقاً مثل قبل.

**حالت کامل (اکانت مدیریت‌شده):** روی «تنظیمات پیشرفته اکانت کلادفلر» بزنید و این‌ها را هم پر کنید — این‌ها را از داشبورد Cloudflare همان اکانت دیگر می‌گیرید:
- **Cloudflare Account ID**: از URL داشبورد کلادفلر (`dash.cloudflare.com/<account-id>/...`) یا صفحه Workers & Pages > Overview، سمت راست.
- **Cloudflare API Token**: از `dash.cloudflare.com/profile/api-tokens` یک توکن جدید با دسترسی حداقلی `Account.Workers Scripts:Read` و `Account.D1:Edit` بسازید (توکنِ کل اکانت با دسترسی کامل هم کار می‌کند، اما توصیه نمی‌شود).
- **D1 Database ID**: از همان پروژه، روی اکانت دیگر، در Workers & Pages > D1 پیدا می‌شود (همان دیتابیسی که آن ورکر جداگانه به آن وصل است).
- **نام اسکریپت ورکر**: نام Worker همان‌طور که در داشبورد آن اکانت ثبت شده (پیش‌فرض این پروژه: `my-vpn`).

با پر کردن این‌ها:
- دکمه «🩺 بررسی سلامت» (تک‌تک یا «بررسی سلامت همه») واقعاً از API کلادفلر می‌پرسد که توکن معتبر است، اسکریپت هنوز روی آن اکانت هست، و خود ورکر آنلاین است — و وضعیت 🟢 سالم / 🔴 مشکل‌دار / ⚪ بررسی‌نشده را نشان می‌دهد.
- هر بار یک کاربر تست/VIP اینجا ساخته، تمدید، یا حذف می‌شود، همان تغییر خودکار در دیتابیس D1 آن اکانت دیگر هم اعمال می‌شود — یعنی همان یک لینک اشتراک، روی هر دو (یا چند) اکانت جداگانه معتبر است.
- اکانتی که «🔴 مشکل‌دار» تشخیص داده شود، به‌صورت خودکار از چرخهٔ کانفیگ‌دهی به کاربران کنار گذاشته می‌شود تا وضعیتش دوباره سالم شود.

> نکته: D1 بین اکانت‌های کلادفلر به‌صورت پیش‌فرض قابل اشتراک‌گذاری نیست؛ همین‌طوری هم که این پروژه معمولاً دیپلوی می‌شود (هر اکانت، دیتابیس خودش را دارد). این بخش دقیقاً همین محدودیت را با «کپی کردن» کاربر VIP روی هر اکانت، از طریق API خود کلادفلر، دور می‌زند — بدون نیاز به هیچ سرویس واسط دیگری.
