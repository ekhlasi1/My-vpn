# راهنمای سرعت بالا، گیمینگ و کاهش فیلترشدن (نسخه v6)

این پروژه روی Cloudflare Workers با **VLESS + WebSocket + TLS** کار می‌کند. چند نکته‌ی مهم قبل از هر چیز:

- Cloudflare Workers **UDP واقعی ندارد** — یعنی هیچ کانفیگ VLESS-روی-Worker نمی‌تواند UDP خام (مثل بعضی بازی‌های آنلاین که روی UDP کار می‌کنند) را واقعاً تانل کند. چیزی که این پروژه می‌دهد، تانل TCP سریع و پایدار است که برای اکثر بازی‌های آنلاینِ مبتنی بر TCP، استریم، و مرورگر عالی کار می‌کند؛ برای بازی‌هایی که صرفاً UDP هستند (مثل بعضی FPSها) سرعت/پینگ محدود به کیفیت تانل TCP باقی می‌ماند.
- کشور مبدأ ترافیک خروجی از Worker همیشه یکی از نودهای Cloudflare نزدیک به سرور شماست، نه یک کشور دلخواه — این محدودیت ذاتی Cloudflare Workers است.

## تنظیمات لینک (سرور-محور، از قبل اعمال شده)

از نسخه‌ی v6 هر لینک VLESS تولیدشده شامل این پارامترهاست:

- `fp=chrome` — فینگرپرینت TLS مثل کروم واقعی (سخت‌تر برای شناسایی DPI)
- `alpn=h2,http/1.1` — هماهنگ با یک مرورگر واقعی
- `ed=4096` — WebSocket Early Data برای هندشیک سریع‌تر
- `add=<آی‌پی سالم>` در صورت وجود — آدرس اتصال از دامنه‌ی sni/host جدا شده (بخش «آی‌پی‌های سالم» در داشبورد)

## تنظیمات سمت کلاینت (باید در اپ کاربر انجام شود — روی لینک قابل embed نیست)

| هدف | تنظیم پیشنهادی |
|---|---|
| کاهش پینگ برای گیمینگ | **Mux را خاموش کنید.** Mux چند اتصال را روی یک کانال می‌ریزد و برای دانلود حجیم خوب است، اما برای گیمینگ باعث jitter/lag spike می‌شود. |
| مصرف کمتر و اتصال‌های همزمان بیشتر (مرور عادی) | Mux را روشن کنید، concurrency را 8 بگذارید. |
| عبور بهتر از فیلترینگ اولیه‌ی TLS | در v2rayNG / Hiddify / NekoBox گزینه‌ی **Fragment** (packet fragmentation روی ClientHello) را با مقادیر `length=10-20, interval=10-20` فعال کنید. این پروژه نمی‌تواند این را از سمت سرور تحمیل کند چون fragment باید قبل از رسیدن به هر سروری، روی خودِ کلاینت اعمال شود. |
| تأخیر اولیه‌ی اتصال کمتر | مطمئن شوید کلاینت از `ed=4096` (Early Data) پشتیبانی و استفاده می‌کند — اکثر کلاینت‌های مبتنی بر Xray این را خودکار از لینک می‌خوانند. |
| DNS سریع‌تر و بدون لو رفتن DNS | DNS کلاینت را روی `https://1.1.1.1/dns-query` (یا هر DoH دیگر) بگذارید، نه DNS سیستم. |

## اگر یک اکانت/سرور جدید به Pool اضافه کردید

بعد از افزودن اکانت جدید در تب «🖧 پنل‌ها»، سیستم **خودکار** همه‌ی کاربران فعلی را به آن sync می‌کند (رفع باگ اصلی نسخه‌های قبلی). اگر به هر دلیلی مطمئن نیستید (مثلاً اتصال شبکه در لحظه‌ی افزودن قطع بوده)، دکمه‌ی **«🔄 Sync دستی همه کاربران به همه اکانت‌ها»** را در همان تب بزنید.

## آی‌پی‌های سالم (Clean IP) خودکار

تب «🌐 آی‌پی‌های سالم کلادفلر» را ببینید. این بخش هر ساعت (همراه با نگهداری زمان‌بندی‌شده‌ی پروژه) چند آی‌پی جدید از رنج‌های کلادفلر را مستقیماً از خود Worker تست می‌کند و بهترین آی‌پی سالم را به‌صورت خودکار در کانفیگ‌های همه‌ی کاربران به‌عنوان آدرس اتصال جایگزین می‌کند — بدون اینکه `sni`/`host` (که مسیریابی واقعی را انجام می‌دهند) تغییر کند. برای تست فوری دسته‌ی بعدی، دکمه‌ی «تست دسته بعدی آی‌پی‌ها همین الان» را بزنید.
